🔴 1순위 Painpoint 선택: Step 6 "확정대기"

왜 Step 6이 가장 부정적인 경험인가?

선택 근거

🎯 손지은의 Persona 특징:
• "자신의 취향과 속도를 지키는 삶을 선호" → 통제 가능한 상황 원함
• "혼자 조용히 쉬는 시간 중시" → 불필요한 반복 확인은 스트레스
• "독립 출판 + 살롱 운영" → 9/15 마감은 실제 사업 제약

처한 상황

⏰ 외부 기한 압박:
• 서점 점주가 9/15에 퇴사 (통제 불가)
• 9/14 상담 후 점주에게 인계 자료 요청 (24시간 이내)
• 상담 확정이 안 되면 9/15 전 자료 수집 불가 (살롱 운영안 정리 실패)

Step 6의 불편이 다른 2점 단계(Step 2)보다 심한 이유

Step 2 (emotion_score: 2): 확인 필요지만, 기한까지 시간 충분
✓ 9/8 아침에 확인 → 9/15까지 7일 남음
✓ 후보 마감 후 재신청 경로 명확

Step 6 (emotion_score: 2): 반복 확인 + 외부 기한 + 자료 준비 불가 위험
✗ 9/8 저녁부터 9/15까지 주기적 확인 필요
✗ 확정 지연 시 9/14 저녁(상담 전날) 점주에게 자료 요청 못 함
✗ "살롱 운영안 정리" 목표 자체가 위협받음 (Persona 꿈 연결)

항목 Step 2 (상태확인) Step 6 (확정대기) ⭐ 1순위
Emotion Score 2점 (긴장) 2점 (긴장)
기한까지 여유 7일 (9/8~9/15) 0일 (확정되면 9/14, 못 되면 실패)
대체 경로 있음 (9/14 오후 재신청) 없음 (9/15가 마지막)
Persona 꿈 영향 간접적 직접적 (살롱 운영안 정리 불가)
수고 비용 앱 1회 확인 반복 확인 + 불안감 + 자료 준비 위험

📍 Step 6: 확정대기 - 상세 분석

6 확정대기 (9/8 저녁 ~ 이후)
😰 긴장 (2점)

현재 시스템 (As-Is)

행동 앱을 주기적으로 열어 9/14 오후 신청 상태(접수됨/확정됨) 확인
기대 9/15 기한 전 9/14 오후 상태가 '확정됨'으로 변경, 상담 예약 시간 고정
실제 관리자 확정 시점이 정해져 있지 않음 → 반복 확인 필요 + 불확실성 지속
불편 관리자 확정 시점 불정으로 반복 앱 확인 필요 + 9/15 마감까지 불확실성 지속
🔴 핵심 Painpoint

"9/14 상담 확정이 절대 필요한데, 언제 확정될지 모르니까
9/8 저녁부터 9/15까지 계속 앱을 확인해야 한다.

그런데 만약 확정이 9/14 오후 2시라면?
상담이 9/14 오후인데, 그 전에 점주님한테 인계할 자료를 정리할 수가 없다.
그럼 살롱 운영안을 정리하는 상담의 목적 자체가 실패한다."

📅 사용자 여정 타임라인

9/7 19:00 9/8 10:00 9/8 14:00 9/8 17:00 9/8 20:00 9/14 9/15 00:00 [신청] [확인] [마감확인] [일정재확인] [재신청] [?] [마감] ✓ 😰 😐 😊 😐 😰 ❌ <--- Step 1 ---> <--- Step 2 ---> <--- Step 3 ---> <--- Step 4 ---> <--- Step 5 ---> <--- Step 6 ---> | Step 2와 Step 6 모두 emotion_score = 2 (긴장) 하지만 Step 6은: • 기한 압박 (9/15 = 마지막 날) • 대체 경로 없음 (9/14만 가능) • Persona 목표 직결 (살롱 운영안 정리) • 자료 준비 시간 부족 (상담 후 24시간 내 점주에게 요청)

🔴 Step 6이 "최악의 순간"인 이유

  • 시간 역전: 9/8 재신청 → 9/14 상담 → 9/15 점주 퇴사
  • 한 번의 기회: 9/14 오후가 유일한 상담 시간 (9/15는 사실상 불가)
  • 자료 준비 시간 0: 상담 후 점주 인계 자료 요청 불가 (점주가 그날 밤 ~ 다음날 아침 퇴사)
  • Persona 목표 위협: "살롱 운영안 정리" 목표 = 이 상담에만 의존
  • 불가역적 결과: 9/15 마지막 날에 확정되면 준비할 시간이 없음

👤 Persona × 상황: 왜 Step 6이 불편한가?

🎯 손지은의 Persona

• 자신의 속도와 취향 중시: 조직 방식 거부
• 독립적: 자신의 결정과 통제 원함
• 꿈 지향적: 살롱 운영 목표 명확
• 시간 여유: 무직이지만 좋은 시간에 불안감 심함

⏰ 처한 상황

• 외부 기한 (9/15): 통제 불가
• 수동 확정: 자신의 의지로 앞당길 수 없음
• 단일 목표: 9/14 상담만이 유일한 경로
• 불확실성: 언제 확정될지 모름 + 알림 없음

📌 Persona × 상황의 마찰

손지은은 "자신의 속도와 통제"를 원하는데,
Step 6에서는 "외부 기한 + 수동 확정 + 불확실성"에 처해 있다.

= 그녀의 가장 피하고 싶은 상황이 현실화됨

💰 정상 운영에서 발생하는 비용

단계 발생하는 비용 이유
Step 1: 신청 없음 한 번의 명확한 입력
Step 2: 상태확인 앱 확인 1회 확인 필요하지만 기한 충분
Step 3: 마감확인 없음 마감 알림 명확, 재선택 경로 있음
Step 4: 일정재확인 개인 일정 재검토 (15~20분) 필요하지만 대체 경로 있음
Step 5: 재신청제출 없음 기능 정상, 새 신청 완료
Step 6: 확정대기 반복 확인 (7일)
+ 불안감
+ 자료 준비 시간 부족 		관리자 수동 확정 시점 미정
+ 외부 알림 없음
+ 9/15 기한 = 최후의 기한
💡 개선 기회

Option 1: 상태 변경 푸시 알림
"24~48시간 내 상태 업데이트 시 자동 알림" → 반복 확인 빈도 70% 감소

Option 2: 기한 기반 자동 처리
"D-2일(9/13) 미확정 시 자동 알림 발송" → 불확실성 해소

Option 3: 대기 상황 명시
"9/14 내 확정 약속" → Persona의 통제감 복구

📌 이 분석의 핵심 내용

🎯 연구 프로세스: Persona → UJM → Painpoint

1단계: Persona 분석
손지은 = 37세, 무직, 살롱 운영 꿈, "자신의 속도와 취향 중시"

2단계: User Journey Map 작성
가상 상황 (서점 인수, 9/15 기한)에서 예약 앱 사용 과정 6단계 분석
각 단계마다 emotion_score 1~5점 부여

3단계: Painpoint 식별
6단계 중 Step 6 (확정대기)가 emotion_score = 2 (긴장)

4단계: 근거 분석
• Persona 근거: "통제 원함" + "속도 중시"
• 상황 근거: "9/15 마지막 기한" + "수동 확정 미정" + "알림 없음"
• 교집합: 가장 피하고 싶은 상황이 현실화됨 (통제 불가 + 불확실성)

결론: Step 6이 emotion_score 2인 다른 단계(Step 2)보다 부정적인 이유는
"긴장의 심도"가 아니라 "기한 압박 + 대체 경로 없음 + Persona 목표 직결"이기 때문

🔍 정상 운영과 불편의 구분

이 분석에서 중요한 점:

✓ 정상 운영: 모든 기능이 제대로 작동함
• 신청 성공, 재신청 성공, 상태 표시 명확
• 시스템 오류, 저장 실패, 버튼 실종 없음

✗ 그럼에도 불편: 정상 기능 때문에 발생하는 비용
• 수동 확정 = 사용자 대기 필수
• 알림 없음 = 사용자 주기적 확인 필수
• 단일 기한 = 대체 경로 없음

💡 개선점: 버그 해결이 아니라 대기의 불확실성을 줄이기
