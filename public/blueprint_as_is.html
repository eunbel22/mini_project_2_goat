💡 의사결정 이유 및 근거 (Satisficing 원칙 적용)

📌 왜 이 대안을 선택했는가? (Satisficing Rationale)

  • 제한된 시간 및 규정 제약: ~15:50 발표 타임라인 및 외부 알림/Edge Function 사용 금지 규정(AGENTS.md) 하에서 외부 이메일/Slack API 연동은 기술적 위험과 오버헤드가 큽니다.
  • 최적화 대신 충족화(Satisficing): 완벽한 오프사이트 알림 인프라 대신, **앱 내 상단 상태 요약 카드(S6-02)**와 **확정 알림 배너(S6-01)**, **대기 중 메모장(S6-08)** 및 **어드민 기한 배지(S6-05)**를 순수 React UI 및 In-App 구조로 구축하는 충분히 만족스러운 대안을 빠르게 결정했습니다.
  • 실질적 가치 창출: 이 대안은 외부 의존성 없이 고객에게 완벽한 통제감과 가시성을 제공하여 반복 확인 피로감을 해소하며, 주어진 조건 내에서 점진적 문제 해결(Incremental problem-solving)을 성공적으로 달성합니다.
